디자인 리뷰는 심판받는 자리가 아니다.
막힌 지점을 함께 뚫고, 팀의 집단 지성으로 퀄리티를 끌어올리는 자리다.
단발 피드백이 아닌 발견 → 패턴 → 원칙화의 사이클이 돌아야 같은 문제가 반복되지 않는다.

01

두 가지로 운영한다

품질 관리는 한 번의 리뷰로 완성되지 않는다. 역할이 다른 두 활동이 맞물려 돌아간다.

디자인 세션

03

디자인 크리틱

진행 중인 작업에 팀 피드백을 받는다. 발표자가 맥락을 먼저 공유하고, 참여자는 질문 → 관찰 → 제안 순으로 이야기한다.

운영 방식

세션 전날
고민 중인 작업을 미리 공유한다. 공유 없이는 크리틱 진행 불가.
공유 내용
① 무엇을 만들고 있나  ② 누구를 위한 것인가  ③ 오늘 뭘 얻고 싶은가  ④ 이미 고민한 것
세션 당일
컨텍스트 5분 → 발표 10분 → 피드백 15분. 안건 없으면 취소.
세션 후
결정사항과 액션아이템을 반드시 기록한다.

피드백 원칙

✓ 이렇게
  • 질문 형태로 시작한다
    "이 플로우에서 사용자가 X 상황이면?"
  • 관찰 → 영향 → 제안 순으로
  • 사용자 목표나 비즈니스 임팩트를 근거로
  • 초기 탐색 단계엔 방향성 피드백만
  • 반영 안 할 피드백은 이유 공유
✗ 이러지 말 것
  • "이거 별로야" — 근거 없는 평가
  • "우리가 늘 해온 방식" — 가장 위험한 말
  • 개인 취향을 팀 기준처럼 말하기
  • 초기 탐색 단계에 세부 지적하기
  • 피드백 후 팔로업 없이 끝내기
04

방향성 얼라인

스쿼드 간 정렬이 필요한 경우 디자인 세션에서 논의한다. 알파푸시·알파업셀·알파리뷰의 UX가 각각 따로 움직이지 않도록 전체 관점에서 대화하는 자리다.

운영 방식

세션 전날
얼라인이 필요하다고 생각되는 것을 미리 공유한다.
주요 논의 주제
컴포넌트·패턴 일관성 / 제품 간 고객 여정 연결 / 용어·카피 통일 / 반복 이슈 원칙화
세션 후
결정된 내용은 반드시 결정 로그에 남긴다. "왜 이렇게 결정했는가"의 근거가 팀 히스토리가 된다.

💡 샐러드랩 핵심 과제 — 알파푸시·업셀·리뷰의 중복 UI 통합, 맥락이 끊긴 기능 연결, 사용자가 이해하기 어려운 용어 개선이 이 세션에서 다뤄져야 한다.

05

UIUX 품질 감사

생각날 때마다 바로 기록한다. 감사 때만이 아니라 일하다 발견한 것도 즉시 테이블에 기입한다. 디자인 리드가 필요하다고 판단될 때 스쿼드 담당자와 1:1로 확인하고 스프린트에 반영한다.

운영 역할

작성자누구나
확인 일정자율 일정 1:1
승인 · 검토디자인 리드
작업자스쿼드 담당자
반영스쿼드 스프린트

4가지 렌즈로 본다

일관성

같은 기능인데 UI가 다르게 구현된 곳. 같은 개념인데 다른 단어를 쓰는 곳.

맥락 연결

함께 써야 하는 기능인데 동선이 끊기는 곳. 맥락이 같은데 따로 떨어진 기능.

엣지케이스

빈 상태, 에러 상태, 로딩 상태가 빠진 화면.

카피 · 용어

의미를 알 수 없는 어려운 용어. 동일 기능에 다른 단어 혼용.

UIUX 품질 감사 테이블

영향도 기준 — High: 전체 플로우에 영향 / Mid: 특정 화면·기능에 영향 / Low: 카피·색상 등 소규모

발견일 제품 렌즈 문제 · 화면 유저 영향 비즈니스 임팩트 영향도 담당 스쿼드 스프린트 상태
04.10 알파리뷰 맥락 연결 리뷰 작성·통계가 다른 메뉴에 분리됨 리뷰 현황 파악에 불필요한 이동 발생 리뷰 활용률 저하 → 재구매 전환 기회 손실 High 리뷰팀 25-09 논의중
04.14 알파업셀 엣지케이스 에러 상태 화면 미설계 오류 발생 시 사용자 이탈 가능성↑ 업셀 노출 중단 → 매출 기회 손실 Mid 업셀팀 25-10 발견됨
04.18 전체 카피·용어 버튼 레이블 혼용 (저장 / 완료 / 확인) 어떤 버튼이 어떤 동작인지 혼란 직접 임팩트 낮으나 신뢰도 저하 Low 전체 25-09 완료
04.20 알파푸시 일관성 필터 컴포넌트 디자인이 타 제품과 상이 제품 전환 시 학습 비용 발생 통합 운영 시 혼란 가중, 지원 비용↑ Mid 푸시팀 미정 발견됨
— 새로운 이슈를 발견하면 바로 추가하세요 —

영향도에 따라 전달 방식을 다르게 한다

영향도 기준 전달 방식 예시
High 전체 플로우 재설계 필요, 비즈니스 임팩트 큼 문서화 후 PO와 1:1 먼저 → 스프린트 반영 기능 분리 구조 개선, 제품 간 여정 연결
Mid 특정 화면·컴포넌트 불일치, 동선 불편 크리틱 세션 안건으로 올리기 에러 상태 미설계, 컴포넌트 불일치
Low 카피 오타, 색상 미스, 레이블 혼용 Figma 코멘트로 바로 전달 버튼 레이블 통일, 오탈자
06

이 순서로 시작한다

한꺼번에 다 갖추려 하지 않는다. 첫 달은 구조보다 문화를 만드는 게 먼저다.

1개월차
발견하고 쌓는다
  • 감사 테이블 만들고 기입 시작
  • 크리틱 세션 첫 시도
  • 아직은 판단보다 발견
  • 디자인 세션 루틴 정착
2~3개월차
패턴을 찾는다
  • 테이블에서 반복 이슈 추출
  • 방향성 얼라인 첫 시도
  • High 이슈 스프린트 반영
  • 데이터로 팀에 공유
3개월차 이후
원칙화한다
  • UX 원칙 초안 제안
  • 결정 로그 누적 관리
  • 월말 성과 공유 정례화
  • 두 활동 완전 정착
